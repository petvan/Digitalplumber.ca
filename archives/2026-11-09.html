Ubuntu fixes FRR regression that broke RPKI revalidation

Ubuntu Security Notice · Nov 5, 2026 · Primary source

The fix for CVE-2024-55553 introduced a regression in RPKI support, causing FRR to stop processing RPKI updates after the first one, so routes were not revalidated when RPKI data changed. In Ubuntu 20.04 LTS, the BGP daemon also failed to start when the RPKI module was enabled.

Why it matters Network operators running FRR on Ubuntu must apply USN-7230-3 to restore RPKI validation—missing this patch leaves routers vulnerable to invalid route acceptance and BGP startup failures on 20.04 LTS.

USN-7230-3 fixes an FRR regression introduced by an earlier vulnerability patch, restoring RPKI update processing and correcting BGP startup failure on Ubuntu 20.04 LTS. The fix for CVE-2024-55553 introduced a regression in RPKI support, causing FRR to stop processing RPKI updates after the first one, so routes were not revalidated when RPKI data changed. In Ubuntu 20.04 LTS, the BGP daemon also failed to start when the RPKI module was enabled. For operators deploying FRR (Free Range Routing) as their BGP implementation on Ubuntu systems: the prior patch (USN-7230-2) inadvertently broke Route Origin Validation (ROV) state machine logic, preventing repeated RPKI cache session updates. This means route revalidation after ROA changes would not occur—effectively disabling RPKI protection. Additionally, 20.04 LTS users experienced total BGP startup failure with RPKI enabled. USN-7230-3 restores both RPKI update processing and daemon startup. Apply immediately if running FRR with RPKI on Ubuntu; confirm BGP daemon starts cleanly and test RPKI revalidation against a public RPKI validator.

OpenSSH authentication bypass exploited in the wild on musl Linux

BleepingComputer · Nov 9, 2026 · Industry news

CVE-2026-123158 (sshole), a CVSS 8.1 password authentication bypass in OpenSSH on musl-based Linux without PAM, is actively exploited in the wild. CISA confirmed exploitation and added to KEV with November 12 deadline; GreyNoise recorded first successful wild exploitation November 7, 40 hours after fix release.

Why it matters Unauthenticated SSH access to passwordless accounts including root on Alpine Linux and other musl systems; Alpine is ubiquitous in Kubernetes, container registries, edge infrastructure, and CI/CD—enabling immediate code execution on cloud-native deployments.

CVE-2026-123158 exploits a flaw in OpenSSH sshd on musl-based Linux systems (Alpine, musl libc) built without PAM. When a password exceeds 256 characters, musl's crypt() function returns an asterisk (*) on error. sshd incorrectly treated this asterisk as a valid hash match for accounts with stored hashes under 4 characters, including passwordless accounts and root. An attacker connects via SSH and enters a 257+ character password to log into any account without providing the correct password. OpenSSH maintainers released version 10.6p2 on November 5, 2026 with a workaround (rejecting stored hashes <4 chars); exploit code appeared within 4 hours. Previdian, watchTowr, GreyNoise, and Defused all detected exploitation attempts starting November 6. GreyNoise confirmed first successful exploitation November 7 at 00:46 UTC. Alpine Linux containers are standard in microservices, Kubernetes, edge routers, and container base images. Every Alpine SSH server exposed to untrusted networks faces immediate compromise risk. Organizations must upgrade OpenSSH to 10.6p2 on all Alpine systems immediately; temporarily disable password authentication (PasswordAuthentication no) until patching completes; monitor SSH access logs for connections using oversized passwords; rotate all credentials on affected systems; scan container images and registries for vulnerable Alpine sshd versions.

SonicWall SSL-VPN flaw lets attackers bypass SAML MFA

SecurityWeek · Nov 6, 2026 · Industry news

CVE-2026-19868 (CVSS 7.1), an authentication enforcement flaw in SonicOS SSL-VPN, allows attackers with valid alternate credentials to bypass SAML authentication and SAML-enforced MFA. Actively exploited; CISA added to KEV with November 20 deadline.

Why it matters Renders multi-factor authentication on VPN ineffective for attackers holding compromised alternate credentials; MFA bypass on perimeter VPN gateways directly enables unauthorized internal network access, defeating the primary control against credential compromise.

CVE-2026-19868 affects SonicWall SonicOS SSL-VPN services when SAML-based authentication is enabled (Gen 7 running SonicOS ≤7.3.3-7015; Gen 8 running ≤8.2.2-8015). An attacker with valid credentials for an alternate authentication method (local LDAP, RADIUS, certificate-based auth) can establish a VPN session without completing SAML verification or MFA challenges enforced by the identity provider. The flaw is not an unauthenticated bypass—attackers require working credentials for at least one authentication method. However, stolen VPN credentials are ubiquitous in breach data; SAML MFA is precisely the control that renders compromised credentials useless. By exploiting this authentication enforcement gap, attackers with single-factor credentials gain full VPN access, bypassing the MFA layer entirely. SonicWall PSIRT investigated reports of potential exploitation and urged customers to patch. CISA confirmed active exploitation and added CVE-2026-19868 to the KEV catalog November 6 with federal deadline November 20. No workarounds exist. Fixed releases: SonicOS 7.3.4-7013 (Gen7) and 8.2.3-8015 (Gen8). Organizations must audit every internet-facing SonicWall instance for SAML configuration; rotate all VPN service accounts and LDAP/RADIUS credentials out-of-band; review authentication logs for SAML bypass patterns (successful logins from SAML-only users via alternate methods); patch all Gen7 and Gen8 appliances to fixed releases immediately.
