SCinet builds SC26's record network on Nautobot source of truth

Network to Code · Nov 17, 2026 · Primary source

SCinet, the temporary supercomputing network at SC26, uses Nautobot as its network source of truth to automate design, deployment, and teardown of a large-scale research network. The platform enables rapid modeling of network infrastructure and automates repetitive tasks like cabling, hardware deployment, and IP schema configuration.

Why it matters Demonstrates Nautobot at production scale in a time-critical, high-stakes environment where network changes must be automated, validated, and reversible—a real-world validation of NSoT-driven automation patterns for practitioners.

SCinet, which connects some of the world's fastest supercomputers and research networks at the annual SC conference, historically built its temporary network manually each November. For SC26 in Chicago, SCinet adopted Nautobot as a shared data foundation across Automation and DevOps teams, automating design and planning workflows that previously took weeks. By modeling the entire network infrastructure in Nautobot before physical deployment, SCinet teams reduced manual configuration tasks (cabling diagrams, IP assignments, device staging) from manual spreadsheet-driven processes to automated workflows. The platform provided a single source of truth that allowed distributed volunteer teams to collaborate safely on a network that must reach production readiness by a fixed date—demonstrating how NSoT platforms enable both speed and safety in large-scale, short-duration network operations. This is not a pilot; it is a full operational deployment automating thousands of devices and connections.

OpsMill opens 2026 Nornir roadmap to community feedback

OpsMill · Nov 16, 2026 · Primary source

OpsMill published a 2026 Nornir roadmap with seven proposals for the Python automation framework, including async inventory support and improved integration with remote sources of truth like Infrahub, NetBox, and Nautobot. All changes are additive and maintain backward compatibility.

Why it matters Nornir's async inventory capability directly addresses a pain point for teams whose NSoT is remote (HTTP/GraphQL APIs); practitioners will be able to load device inventory from NetBox/Nautobot/Infrahub without blocking task execution, improving performance on large inventories.

Nornir's roadmap emphasizes three principles: the architecture stays small and focused; new capabilities are delivered as plugins; all changes are additive with no breaking changes to existing code. Key proposal: async inventory support extends Nornir's runner concurrency to the inventory loading phase itself. Many teams store device inventory in HTTP or GraphQL APIs—Infrahub, NetBox, Nautobot—and the inventory plugin can spend significant time waiting for remote requests. Async inventory removes that blocking behavior, allowing teams to load thousands of devices in parallel. The roadmap also proposes improved plugin extensibility and tighter integrations with modern infrastructure-as-code tools. OpsMill committed to a stable 3.7 release within four to six weeks if testing proceeds on schedule. This is not a major rewrite; it is careful, community-driven incremental improvement aligned with how automation teams actually use Nornir.

Lambda runs Nvidia co-packaged optics in 10,000-GPU cluster

TechTarget · Nov 17, 2026 · Industry news

Lambda has deployed Nvidia's co-packaged optics technology in an AI cluster connecting more than 10,000 Blackwell Ultra GPUs, demonstrating production-scale CPO viability. Nvidia said each CPO switch replaces 25-watt, 1.6-Tb/s transceivers with optical components consuming five watts for the same bandwidth, amounting to a potential 1.44-kilowatt reduction per switch in optical-component power across 72 transceivers.

Why it matters CPO power reductions accelerate 1.6T optics ROI at scale; validates architecture for 128K+ GPU fabric planning and power budgeting in production data center builds.

Lambda's Quebec deployment of NVIDIA's co-packaged optics (CPO) with Spectrum-X Photonics switches marks the first significant production use of integrated photonic engines in hyperscale AI clusters. The architecture integrates optical components directly on the switch package rather than using pluggable transceivers, reducing electrical trace lengths and signal loss. NVIDIA's power comparison shows each optical transceiver component dropping from 25W to 5W—a 5x reduction—though total switch power also improves from an estimated 7kW (conventional) to 3.95kW (CPO). Lambda's modeling suggests a 128,000-GPU data center would need approximately 655,000 discrete transceiver modules with conventional pluggable optics, each consuming power and representing a failure point. The CPO architecture eliminates this mechanical and thermal overhead. While NVIDIA's component-level power savings are modeled rather than measured at Lambda's site, the deployment validates that CPO switches can reach production scale with AMD Instinct accelerators and function reliably in a managed AI cloud environment. This matters for practitioners planning 2027-2028 AI fabric refreshes where power density is becoming the binding constraint on GPU cluster scale.

China-linked group exploited critical VMware vCenter bypass since September

Google Threat Intelligence Group / Mandiant · Nov 19, 2026 · Primary source

A suspected China-linked espionage group ARMORY CASTLE exploited CVE-2026-123890, a critical authentication bypass (CVSS 9.8) in VMware vCenter Server Directory Service, in early September 2026. The group used a custom tool called BONESAW to enable remote LMDB exfiltration, SAML STS hijacking, and SSO administrator account creation on vCenter servers.

Why it matters There is no workaround; vSphere teams need both the update and a compromise review. Virtualization infrastructure compromise represents complete infrastructure control and lateral movement capability.

ARMORY CASTLE (formerly UNC5221) exploited this zero-day from at least early September, more than two months before Broadcom released a fix on November 19 in advisory VMSA-2026-0009. CVE-2026-123890 is an unauthenticated Secure Remote Password (SRP-6a) session key disclosure vulnerability over Distributed Computing Environment/Remote Procedure Calls (DCE/RPC). Port 2012 is used as the control interface RPC for vCenter Single Sign-On (SSO) and was integral to the remote exploitation. After creating a listener on TCP port 33992, ARMORY CASTLE moved laterally to the vCenter appliance as Administrator, created local admin accounts, and enabled SSH via the vCenter Server Appliance Management Interface (VAMI) API. Fixed in vCenter 9.1.1.0200, 9.0.2.0200 and 8.0 U3m. The two-month unpatched window and use of specialized malware indicates nation-state-grade targeting of virtualization infrastructure.

Attackers root Cisco Expressway clusters via hard-coded credentials

Secure.com / CISA KEV Catalog · Nov 20, 2026 · Primary source

CVE-2026-76466 (CVSS 9.8), a critical flaw affecting Cisco Expressway Series clustered deployments, involves hard-coded credentials and insufficient validation of client certificates. On November 19, attackers rooted four clustered Expressway X15.5.3 devices at a Russian organization, two weeks after exploit code appeared on GitHub.

Why it matters A maintenance identity and its cookie are hard-coded into the software and are the same on every install, allowing anyone who can reach port 4372 to join the cluster and run commands as root without a password. Cisco collaboration edge gateways are internet-facing perimeter devices critical to call control.

CISA added CVE-2026-76466 to its Known Exploited Vulnerabilities catalog on November 20 with a November 23 deadline; Cisco fixed it on October 21 in Expressway X15.5.20. The bug sits in the cluster database service, which runs on Erlang and listens on TCP 4372. Once inside, attackers ran custom Python scripts that scanned for SMB shares, probed SQL Server and WinRM, and pulled credentials from internal GitLab repositories. X14 and earlier have no fix, so Cisco recommends migrating to a fixed release. Cisco lists no workaround. The hardcoded nature means every Expressway install worldwide shares the same exposed credential.

On November 10, CISA added six vulnerabilities including CVE-2026-20320 (Cisco BroadWorks XXE), CVE-2026-116606 (Barracuda ESG auth bypass), and CVE-2026-111560 (Barracuda OS command injection).

Why it matters Email gateways (Barracuda), voice/comms platforms (Cisco BroadWorks), and NAS devices (Synology) are high-value targets; OS command injection and auth bypass flaws in gateway appliances directly expose internal networks to unauthenticated RCE.

Barracuda flaws are particularly significant for network operations teams: CVE-2026-116606 is an authentication bypass using an alternate path or channel in Email Security Gateway, and CVE-2026-111560 is an OS command injection affecting multiple Barracuda products. These gateway appliances sit at network edges and control mail traffic for millions of organizations. Network administrators should prioritize email security appliance patching alongside CISA deadline compliance. CVE-2024-10441 in Synology DSM is being actively exploited for C3RB3R ransomware deployment on network-attached storage.

Paper maps open problems in scale-up accelerator fabrics

arXiv · Nov 19, 2026 · Research

Paper analyzing networking challenges for AI accelerator interconnects. Authors assess topology, protocol mechanisms, and system integration requirements for high-bandwidth, low-latency scale-up fabrics used in distributed training and inference workloads.

Why it matters Scale-up networking directly impacts cluster performance for large AI training jobs; this paper provides architectural foundation for evaluating and designing next-gen interconnects.

Tingting Xu and 11 co-authors from leading cloud/accelerator companies analyze the design space for scale-up fabrics—tightly coupled accelerator networks combining high per-device bandwidth with low, predictable latency. The paper moves beyond vendor-specific implementations to establish a requirements-driven framework for topology, protocol mechanisms, communication semantics, and system integration decisions. Scale-up networking has become a critical bottleneck as model sizes expand; existing solutions (custom ASICs, proprietary protocols) lack standardization. This work provides practitioners with a systematic way to evaluate trade-offs between technologies like optical switching, packet-based switching, and hybrid approaches, and to understand how protocol choices interact with topology constraints. The paper acknowledges that topology, protocol, and system design remain actively debated, making a unified framework valuable for infrastructure teams sizing AI cluster investments.

IETF draft adds post-quantum forward secrecy to EAP-AKA'

IETF · Nov 18, 2026 · Primary source

New IETF draft specifies post-quantum key encapsulation updates to RFC 9678 for EAP-AKA' reauthentication. Addresses forward secrecy and hybrid post-quantum cryptography in mobile and wireless authentication protocols.

Why it matters Mobile and cellular networks need post-quantum-resistant authentication; this draft guides operators on upgrading EAP-AKA' implementations before quantum computers threaten current cryptography.

Draft-ietf-emu-fs-reauth-00 updates forward secrecy provisions in RFC 9678 (EAP-AKA') to incorporate post-quantum key encapsulation mechanisms and hybrid post-quantum approaches. EAP-AKA' is widely deployed in 3GPP mobile networks for user authentication and key establishment. The draft allows systems to combine classical and post-quantum key encapsulation in reauthentication flows, critical because traffic encrypted today with keys derived from current reauthentication could become vulnerable to future quantum attacks. Network operators planning multi-year upgrades must track this work to understand migration timelines and testing requirements for devices in the field that will authenticate through networks for years to come.
