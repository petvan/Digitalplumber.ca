Cloudflare cuts DNS zone build memory use by 86%

Cloudflare Blog · Nov 2, 2026 · Primary source

Cloudflare built a targeted DNS Zone Builder that cuts full zone rebuilds by 40%, reduces peak memory from 79 GiB to 7 GiB (86% reduction), and halves median build completion delay from 7.7 to 3.3 seconds by determining the smallest safe rebuild rather than always rebuilding entire zones.

Why it matters Large-platform performance gains now come from classifying internal changes precisely to skip expensive work without serving stale DNS data; the 85% peak-memory cut and halved median build delay represent capacity and tail-latency gains inside Cloudflare's infrastructure that operators should understand when evaluating DNS platform scalability.

Cloudflare rebuilt its DNS Zone Builder with a targeted build planner and unified scheduler to rewrite only the parts of a zone that changed, instead of rebuilding entire zones for every setting change. Full builds dropped by about 40%, with 92.95% of builds now avoiding a complete zone rebuild over a 24-hour window. Peak working-set memory fell from 79 GiB to 12 GiB, an 85% reduction, and the largest p99 build delay spike fell from 14.6 minutes to 1.21 minutes. The extra headroom let Cloudflare shorten internal wait times, halving median build completion delay from about 7.7 seconds to 3.3 seconds. The DNS pipeline now handles nearly three times the changes it did in 2022. Full builds still happen for first-time zone publication or when an event's effect is unclear, but these make up only 7.04% of builds and average just 0.35 seconds. This work addresses scalability at the DNS authoritative side—relevant to operators running large zone counts or evaluating DNS infrastructure partners for performance and resource efficiency.

Ivanti zero-days chain to unauthenticated root, added to KEV

Rapid7 / CISA / SecurityWeek · Oct 30, 2026 · Primary source

CISA added CVE-2026-111357 (CVSS 8.8, privilege escalation) and CVE-2026-118527 (CVSS 4.3, predictable file upload) to KEV on October 30; both chain with CVE-2026-104935 to enable unauthenticated root-level code execution on Ivanti Connect Secure. Threat group UTA0576 exploited the full chain beginning October 3, 2026.

Why it matters Remote-access gateway compromise chains allow attackers direct enterprise core access; organizations must immediately upgrade all Connect Secure appliances to patched versions (25.1.1.3 or 22.8R2.6) and rotate credentials before federal deadline of November 2–13, 2026.

On October 29, 2026, Ivanti updated its security advisory for Ivanti Connect Secure (ICS) to include two additional vulnerabilities and released fixes for both. On October 30, 2026, CVE-2026-111357 and CVE-2026-118527 were added to the U.S. KEV catalog. In its investigation, Volexity reports that UTA0576 used an exploit chain to gain unauthenticated root access to an appliance running 22.8R2.4, beginning on October 3, 2026. CVE-2026-111357 has a CVSS severity score of 8.8 and results from missing authentication for a critical function. An authenticated attacker with local access could exploit it to gain higher privileges. CVE-2026-118527 involves predictable identifier generation. Affected: Connect Secure 25.1.1.2 and prior, 25.1.2.2 and prior, and 22.8R2.5 and prior. The exploit chain: skip the login with CVE-2026-104935, upload a file to a guessable path with CVE-2026-118527, run code as the web user, escalate to root with CVE-2026-111357, then read stored domain credentials. CISA gave Federal Civilian Executive Branch agencies until November 2 to fix CVE-2026-111357, three days after the October 30 listing, and until November 13 for CVE-2026-118527.

GitLab RCE and Cisco firewall DoS flaws exploited in wild

CISA / The Hacker News / Cisco · Oct 30, 2026 · Primary source

CISA added CVE-2026-97229 (CVSS 10.0, GitLab RCE via integer overflow in CI/CD regex validation) and CVE-2026-76418 (CVSS 8.6, Cisco ASA/FTD null pointer dereference DoS) to KEV on October 30. GitLab flaw allows unauthenticated code execution; an attacker probed Alpine Linux's GitLab on October 20–21.

Why it matters Perfect-score GitLab RCE threatens any developer pipeline using self-managed instances; Cisco firewall DoS flaws allow attackers to disable perimeter security mid-attack. Both require immediate patching by November 1, 2026 (federal deadline).

CVE-2026-97229 (CVSS score: 10.0) is an integer overflow or wraparound vulnerability in GitLab Community Edition and Enterprise Edition that could allow an unauthenticated user to execute arbitrary code on the GitLab server via a specially crafted regular expression in a CI/CD configuration due to insufficient regular expression validation. Alpine Linux reported that an unknown attacker tried to exploit the vulnerability on October 20 and 21, 2026, but the attempts failed. CVE-2026-76418 scores 8.6 and affects Cisco's Secure Firewall ASA and FTD software—the appliances many organizations use as their front door to the internet. A flaw in how the software handles a return value can let an unauthenticated remote attacker force the device to reload unexpectedly, allowing denial of service. Affected releases include GitLab 19.2 versions before 19.2.8, 19.3 versions before 19.3.5, and 19.4 versions before 19.4.2. CISA orders federal agencies to fix both vulnerabilities by November 1st, 2026.

Attackers exploit PHP flaws on exposed PAN-OS management interfaces

CISA / Palo Alto Networks / BleepingComputer · Oct 27, 2026 · Primary source

Two critical PHP vulnerabilities (CVE-2026-109618, CVE-2026-109619, CVSS 9.2 each) allow unauthenticated remote code execution on PHP systems. Palo Alto reported active exploitation targeting internet-exposed PAN-OS management interfaces on October 29; threat actors extract credentials and enumerate Active Directory after gaining RCE.

Why it matters Network appliances with exposed management interfaces are primary targets; PHP2Shell enables unauthenticated RCE directly on firewalls and edge devices. Restrict management interface access immediately, scan for exposure, and apply patches across all affected products (Palo Alto, Fortinet, Cisco, GitLab).

Two critical vulnerabilities, CVE-2026-109618 and CVE-2026-109619, known as PHP2Shell, allow unauthenticated remote code execution on PHP systems serving web requests. Threat actors without privileges can exploit these in attacks to gain RCE on unpatched systems. Palo Alto Networks warned that threat actors are exploiting the recently patched PHP2Shell vulnerabilities against publicly-accessible management interfaces. Active exploitation has been observed targeting the Palo Alto Networks management interface exposed to the internet. As of October 30, 2026, patches have been released for all vulnerable versions of PAN-OS 12.2, PAN-OS 12.1, PAN-OS 11.2, PAN-OS 11.1, and PAN-OS 10.2. The affected devices run specific versions of firewall software; the attacker then launched attacks against Active Directory. Recovered artifacts confirm credential extraction and directory enumeration.

Why it matters Early 6G design decisions now will determine whether autonomous network operations are native or retrofitted—a critical inflection for NetDevOps and AIOps practitioners planning network evolution strategies.

Verizon CTO Yago Tenorio says 6G needs an architectural rethink to handle AI-driven uplink demand, avoid repeating 5G's standardization mistakes, and embed autonomous network operations and commercial use cases from the outset. This isn't a 2030 problem—it's a standards-shaping problem now. Verizon ran 70 million closed-loop automation processes in 2025. Verizon wants use cases such as ISAC to shape the standard, while embedding network autonomy from launch rather than bolting it on later. For operators planning RAN transformation, this signals the industry direction: autonomy-first architecture is becoming table stakes for next-generation networks.
