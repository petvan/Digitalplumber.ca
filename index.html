BGP hijack redirects Chinese web traffic to gambling sites

Tribuna · Nov 11, 2026 · Industry news

Internet users across several Chinese provinces were redirected to gambling platforms after attackers exploited BGP rules through AS 402425 to override legitimate routes via longest-prefix match, substituting official addresses with gambling-site destinations or malicious DNS servers.

Why it matters BGP route incidents occur hundreds of times monthly and most go unnoticed; this incident shows why route filtering and RPKI enforcement matter operationally for traffic hijacking prevention at scale.

Malicious actors exploited BGP rules through autonomous system AS 402425, registered in April 2026 by US-based Qorexa Labs, to announce false routes and tamper with DNS responses. The hijack leveraged the longest-prefix match rule where a more specific prefix overrides a broader legitimate route. While measurements pinpointed tampering within AS 402425, investigators noted analysis does not establish intent by the company. CNCERT urged international registries to review and revoke malicious AS resources and recommended operators filter routes containing AS 402425. This demonstrates BGP attack vectors remain viable at scale through registered but malicious ASNs. For operators, it underscores importance of ingress filtering, active route monitoring beyond RPKI, and coordinated incident response with transit providers.

Critical FortiOS flaw lets attackers forge BGP and OSPF routes

Red Tiger Security, Fortinet PSIRT · Nov 10, 2026 · Analysis

Fortinet released fixes for CVE-2026-126253 (CVSS 9.3), a critical flaw in FortiOS allowing unauthenticated attackers to send specially crafted requests that cause firewalls to broadcast malicious routing announcements. Also patched: CVE-2026-126261 (unauthenticated RCE on FortiManager via FGFM channel).

Why it matters Unauthenticated BGP manipulation creates routing hijacking and instability risks across branch networks and SD-WAN deployments. This affects network core infrastructure stability, not just individual device security.

CVE-2026-126253 is an authentication bypass in the OSPF daemon affecting FortiOS 8.0.0–8.0.1, 7.6.0–7.6.7, 7.4.0–7.4.12, and 7.2.0–7.2.13 on devices with OSPF enabled. CVE-2026-126254, a numeric truncation error in BGP handling, allows an iBGP neighbor to propagate malicious attributes to connected routers; this impacts larger networks with dynamic routing, SD-WAN, and multiple branches. Additional unauthenticated, network-reachable flaws include CVE-2026-126148 (CVSS 9.8, OS command injection in FortiMail), CVE-2026-126170 (CVSS 9.8, RCE in FortiAnalyzer and FortiManager), and CVE-2026-126262 (CVSS 9.8, SQL injection in FortiAnalyzer and FortiManager). Fortinet reports no known exploitation as of November 10, 2026, and fixed versions are available. However, routing protocol flaws have historically attracted fast exploitation once details circulate; teams managing multi-branch and SD-WAN deployments should prioritize updates to core firewall and management infrastructure.

Microsoft patches unauthenticated RCEs in DNS, LDAP and Exchange

OPSWAT, Zero Day Initiative, Microsoft · Nov 12, 2026 · Analysis

Microsoft released 1,094 CVEs including CVE-2026-119958 (LDAP unauthenticated RCE on every domain controller) and CVE-2026-88218 (Windows DNS unauthenticated RCE, CVSS 9.8). Only one flaw is under active attack: CVE-2026-124194 (Microsoft Outlook spoofing zero-day).

Why it matters Unauthenticated RCEs in DNS, LDAP, and Exchange directly threaten Active Directory and nameserver availability. These are mass-exploitation candidates affecting infrastructure teams running Windows infrastructure estates.

CVE-2026-119958 is an out-of-bounds write in LDAP that unauthenticated attackers can trigger over the network with no user interaction; LDAP runs on every domain controller, putting directory infrastructure in direct scope. CVE-2026-88218 affects Windows DNS Server (CVSS 9.8) on systems co-resident with Active Directory. Exchange Server carries CVE-2026-118207 (RCE). The SMB Server transport driver holds CVE-2026-113825, and the TCP/IP stack holds CVE-2026-113859, both critical RCEs. DNS has 33 CVEs between Windows DNS and DNS Server components, with 10 of them RCEs and 13 scoring only 4.9. DHCP Server carries 9 bugs including 4 RCEs. These flaws are not yet widely exploited but their network-reachable, unauthenticated nature makes them mass-exploitation candidates. Prioritize patching domain controllers, DNS servers, and Exchange infrastructure first.

AWS fixes SSRF flaw in MCP gateway registry

GBHackers · Nov 13, 2026 · Industry news

AWS disclosed a server-side request forgery (SSRF) flaw (CVE-2026-125926) in mcp-gateway-registry that lets authenticated users make the gateway send requests to internal services. AWS fixed the issue in version 1.35.0 with upstream address validation.

Why it matters With thousands of MCP servers already vulnerable, infrastructure ops teams must treat MCP registries as high-value targets and update immediately; adds critical security considerations to agentic infrastructure architectures.

The registry centralizes discovery, access control, and proxying of MCP tool assets. A vulnerability existed in the server registration and update API which failed to validate the upstream address of a registered server. A user with permission to register or modify servers could redirect that address to an internal service, enabling lateral movement to databases, cloud metadata endpoints, and internal APIs. Attackers already target this path; researchers recently observed MCP reconnaissance paired with cloud metadata SSRF to steal credentials. AWS rates the bulletin Important (8.5 High under CWE-918). As MCP becomes the standard interface for AI agents accessing network and cloud infrastructure, the registry itself becomes a high-value attack target. Any team deploying MCP servers for agent-driven operations should update mcp-gateway-registry immediately and audit registries for unauthorized server registrations that might point to internal services.

IETF draft sets requirements for inter-domain source address validation

IETF DataTracker · Nov 6, 2026 · Primary source

Updated IETF draft addressing inter-domain source address validation (SAV) mechanisms, analyzing gaps in current validation techniques and defining requirements for improved security against source address spoofing at network boundaries.

Why it matters Operational teams deploying DDoS mitigation and anti-spoofing controls need awareness of evolving SAV standards; this draft shapes the future of BGP-based ingress filtering and border router configurations.

The SAVNET working group continues refining inter-domain source address validation approaches. Draft version 23 was updated November 6, 2026, as the group advances toward Informational RFC status. The document catalogues existing validation mechanisms (ACLs, loose uRPF, strict uRPF) and their limitations across different traffic scenarios and customer cone configurations. SAV rules prevent packets with spoofed source addresses from entering the network, but current approaches have blind spots: improper blocks (legitimate traffic rejected due to inaccurate rules) and improper permits (spoofed packets allowed through). The draft's requirements-based approach aims to guide design of new SAV mechanisms that improve accuracy without requiring routing policy overhauls. For network operators, this is directly relevant to source-based DDoS mitigation and inter-AS filtering strategies. Understanding these gaps helps ops teams evaluate vendor implementations and plan for standards-based controls beyond today's BGP-based defenses.

Janus framework pairs digital twins with LLM network orchestration

arXiv · Nov 11, 2026 · Research

arXiv paper proposing Janus, an LLM-based agentic framework unifying digital twin construction and network orchestration in closed-loop systems for large-scale 6G networks.

Why it matters AIOps and network automation teams exploring AI-driven network modeling should track agentic approaches that couple real-time digital twins with orchestration; this represents evolving patterns for autonomous network management at scale.

Janus (arXiv:2611.14920, accepted to IEEE GLOBECOM 2026) addresses a key gap in operational network management: the decoupling between network modeling and actual control. Conventional approaches use static models for digital representation, then apply orchestration separately, limiting adaptability in large-scale, heterogeneous, dynamic 6G networks. The paper proposes an agentic LLM framework that integrates both roles: the agent simultaneously constructs an evolving digital twin from live network data and makes orchestration decisions based on that model, creating a feedback loop. For operators, this signals the direction of AI-assisted network management: instead of separate tools for modeling and control, future systems will embed learning and decision-making within the same agent. The authors acknowledge next-gen wireless networks are increasingly large-scale and heterogeneous, making static models obsolete. This work is preliminary but published in a top-tier venue, indicating growing academic and industry interest in agentic network automation. Relevant to teams building AIOps platforms or considering LLM integration for closed-loop network control.
