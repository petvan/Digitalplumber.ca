Nautobot patches REST API permission leak in connected device endpoint

GitHub · Nov 23, 2026 · Primary source

Nautobot v2.4.47 fixes the connected-device REST API endpoint to properly render connected devices in brief form when the requesting user lacks permission to view full details. This security fix ensures proper permission boundaries in Nautobot's REST API.

Why it matters API permission handling is critical for multi-tenant and role-based access control in network source-of-truth platforms. Proper gating of sensitive device information based on user permissions is essential for enterprises using Nautobot as a shared inventory source.

Nautobot v2.4.47 fixes the connected-device REST API endpoint to render the connected device in a brief {id, object_type, url, display} form when the requesting user does not have permission to view it. This addresses a potential information leakage in Nautobot's REST API where connected devices could expose data to users without proper permissions. For automation teams using Nautobot as a network source of truth in multi-tenant environments, this ensures that role-based access controls properly gate sensitive network topology and device data accessed through the REST API, preventing unauthorized visibility into connected infrastructure. This is especially important when Nautobot serves as the inventory backend for orchestration platforms like Itential or Nornir scripts that may operate under various service accounts with different permission levels.

Dynatrace adds causal AI root cause analysis and automated remediation

Dynatrace · Nov 16, 2026 · Primary source

Dynatrace released an enhanced AIOps capability leveraging causal AI to deliver precise root cause analysis and automated remediation across complex IT environments, moving beyond threshold-based alerting.

Why it matters Causal AI narrows false positives and accelerates MTTR by pinpointing actual fault chains rather than symptom correlations, reducing alert noise that plagues NOC operations in hybrid environments.

Dynatrace's enhanced AIOps capability is built on causal AI rather than correlation rules, delivering deterministic root cause analysis that identifies the actual sequence of faults causing an incident rather than merely detecting co-occurring symptoms. This addresses a persistent operational weakness: traditional AIOps platforms correlate alerts based on temporal proximity or statistical likelihood, often producing low-confidence recommendations that require human verification. Causal AI analyzes event chains and dependency graphs to establish "if A failed, then B follows because C caused both." The platform integrates this with automated remediation pathways, allowing operators to execute fixes programmatically once a root cause reaches a confidence threshold. This matters for NetOps teams managing hybrid cloud, on-premises, and edge infrastructure: network-induced latency cascades can appear as application errors, database timeouts, and middleware crashes simultaneously. Causal analysis isolates whether the network is the root cause, a contributor, or a bystander—critical for handing clean evidence to application teams rather than creating inter-team finger-pointing. Dynatrace frames this within its broader observability platform, covering infrastructure, applications, logs, and digital experience signals, so causality analysis incorporates all layers simultaneously.

Why it matters Co-packaged optics moved from lab demo to production deployment—practitioners planning 10K+ GPU clusters can now evaluate CPO for power budgets and reliability, with CPO significantly lowering power consumption by eliminating long copper traces from switch chip to front-panel pluggables.

NVIDIA's first generation is in Quantum-X switching product, while Spectrum-X will be an updated second-generation part. Co-packaged optics scale-out is now in volume production. NVIDIA uses an array of 18 pluggable light sources on the front of the chassis to generate light en route to the switch package's optical modules, with those light sources being pluggable for serviceability—a key inhibitor when light sources were integrated. For infrastructure teams, CPO is production-ready and indicates hyperscale rollout capability in 2027, though serviceability and standardization across non-NVIDIA suppliers remain open questions.

BGP anomaly detectors miss up to 41% of anomalies elsewhere

RIPE Labs · Nov 23, 2026 · Research

RIPE NCC researchers built a BGP anomaly detector using public Routing Information Service data and tested it blind on a network for three days, raising four alerts within an hour on the second morning that correctly matched actual incidents. Benchmarking 13 synthetic BGP traffic generation methods found detectors with near-perfect scores on their home collector missed 35-41% of anomalies on different collectors.

Why it matters Anomaly detector accuracy varies dramatically across collectors; operators need realistic expectations on cross-infrastructure effectiveness, especially with ASPA adoption at only ~4% of routed ASNs by November 2026.

RIPE NCC researchers deployed a BGP anomaly detector built with nothing but public RIS data, testing it blind for three days on an unfamiliar network; on the second morning it raised four alerts within about an hour, with the times correctly sent to the network's operations team to validate against actual incidents. The model observes BGP only—in blackout scenarios it detects the routing breakdown rather than the underlying power failure. Critically, benchmarking 13 methods for generating synthetic BGP traffic showed that a detector achieving near-perfect accuracy on its home collector missed 35-41% of anomalies when tested on a different collector, exposing significant cross-collector generalization gaps that undermine operator confidence in outsourced anomaly detection. ASPA (Autonomous System Provider Authorisation) for path-level validation stands at only ~4% adoption among routed ASNs by November 2026, limiting anomaly detector effectiveness against path manipulation attacks beyond origin validation.

Attackers exploit hard-coded credentials in Cisco Expressway clusters

Infosecurity Magazine · Nov 23, 2026 · Industry news

CISA added CVE-2026-76466 to its Known Exploited Vulnerabilities catalog on November 20 after active exploitation reports. The critical flaw allows unauthenticated remote attackers to execute OS commands as root in Cisco Expressway clustered deployments via hard-coded credentials and persistent cookies.

Why it matters Internet-facing Expressway devices are compromised with root access enabling lateral movement into internal networks; federal agencies must patch by November 23 under BOD 22-01; immediate restriction of ports TCP/4371–4372 or upgrade to X15.5.20+ is required.

Threat actors have been observed exploiting CVE-2026-76466 to breach organizations, with attackers compromising internet-facing Cisco Expressway devices and pivoting to internal cluster nodes. The vulnerability has a CVSS score of 9.8 and sits in the database service that Expressway cluster peers use—the service relies on persistent cookies and does not validate client certificates when cluster TLS verify mode is enabled. If immediate patching is not possible, restricting connections to ports TCP/4371–4372 at the firewall and allowing access only from trusted cluster node IP addresses is the recommended workaround. This is a critical network-infrastructure event because Expressway devices are internet-facing access gateways, and root-level compromise enables unrestricted lateral movement into internal networks, making urgent patch deployment mandatory across all network operations teams.

CISA flags four exploited flaws in Cisco, VMware, SAP and Roller

SC World · Nov 22, 2026 · Industry news

CISA added four actively exploited critical vulnerabilities to its Known Exploited Vulnerabilities catalog on November 20–22: CVE-2026-76466 (Cisco Expressway hard-coded credentials RCE), CVE-2026-123890 (VMware vCenter authentication bypass), CVE-2025-42884 (SAP NetWeaver unauthorized data access), and CVE-2026-129448 (Apache Roller deserialization RCE). Three carry CVSS 9.8 ratings.

Why it matters Federal agencies must remediate all four by November 23 under BOD 22-01; enterprise network teams should prioritize these across infrastructure management platforms, virtualization, and messaging systems in the same critical window to prevent supply-chain and central-platform compromise.

Nine actively exploited vulnerabilities were added to the CISA KEV catalog between November 16–22, 2026. The four highest-impact entries affect network infrastructure: SAP NetWeaver (common in enterprise data centers), VMware vCenter (central management layer for virtualized infrastructure), Apache Roller (affects content management in some organizations), and Cisco Expressway (internet-exposed access gateway). All are in active exploitation. Network teams should cross-reference their inventories against this list and prioritize patching in deployment order: Expressway first because it is internet-exposed with root access, then management platforms (vCenter, SAP), then data-layer applications. The vCenter entry is particularly notable because it is linked to China-nexus threat actor ARMORY CASTLE, suggesting coordinated exploitation in espionage campaigns.

Palo Alto patches unauthenticated RCE in PAN-OS and Panorama

GBHackers · Nov 23, 2026 · Industry news

Palo Alto Networks disclosed two critical NGINX vulnerabilities (CVSS 9.2) in PAN-OS and Panorama that allow unauthenticated remote code execution or worker process crashes on affected deployments. No active exploitation reported; fixed builds available November 23 for PAN-OS 11.2.8 and later.

Why it matters Internet-facing firewalls and Panorama management consoles require immediate version audit and patching; fixed builds are 11.2.10-h19, 11.2.13-h6, and 11.2.16-h3; versions earlier than 11.2.8 are unaffected; network teams should confirm patch availability and schedule upgrades on perimeter and central management platforms.

Palo Alto Networks published its advisory on November 21, 2026, assigning CVSS 9.2 base score and moderate response urgency. The vendor rates attack complexity as high but says exploitation requires neither credentials nor user interaction. This is a perimeter firewall and central management event affecting NGFW deployments: Panorama is the centralized configuration and logging platform for Palo Alto firewall estates, making a Panorama compromise especially dangerous because it allows attackers to push malicious rules or configurations to all managed firewalls. While the advisory indicates high attack complexity and no current exploitation, the combination of zero authentication requirement and CVSS 9.2 on internet-facing management interfaces demands rapid assessment and patching. Network operations teams running PAN-OS should audit their version inventory immediately: pre-11.2.8 deployments are unaffected, but 11.2.8 through 11.2.16 require the specific hotfixes.
