Unimus adds native MCP support for AI-driven network changes

Packet Pushers · Nov 10, 2026 · Industry news

Unimus, a network configuration management platform, is adding native Model Context Protocol (MCP) support in an upcoming release, enabling AI agents to govern network changes. This briefing was conducted ahead of AutoCon 6.

Why it matters MCP integration reduces friction for AI-driven automation by giving agents standardized access to configuration backups, auditing, discovery, and change management—critical for governed network automation at scale.

Unimus provides network configuration management including backups, auditing, device discovery, and automated change management. The addition of native MCP support allows AI agents to interact with Unimus as a standardized tool interface, following the Model Context Protocol pattern that has emerged across infrastructure tooling. This is particularly relevant for teams building agentic network automation workflows where natural language or LLM-driven decisions need to be translated into actual network changes. MCP servers provide governed access—the agent can query Unimus for current state, propose changes, and trigger deployments within defined guardrails. Unimus bridges the gap between older configuration management practices and the emerging pattern of AI agents coordinating infrastructure changes across multiple tools. The timing (AutoCon 6 briefing) suggests this is part of a broader ecosystem shift toward agent-native network orchestration tooling.

Seven network automation tools compared on AI agent integration

NetPilot · Nov 10, 2026 · Analysis

Comparison of seven network automation tools and how they integrate with AI agents via MCP, including NetBox, Nautobot, IP Fabric, Itential, and containerlab. Evaluates source-of-truth inputs, agent connectivity, and integration patterns.

Why it matters Practitioners choosing between source-of-truth platforms and orchestration engines now must consider MCP-first design: which tools expose read-only queries, custom integrations, and API surfaces that agents can safely consume without breaking automation reliability.

The analysis ranks tools across two dimensions: source-of-truth input (discovered from live network vs. recorded in NetBox/Nautobot vs. indirectly via integration) and agent connectivity (whether they publish an MCP server, support custom integrations, or require workarounds). NetBox Labs publishes the most "agent-forward" source of truth with an open-source MCP server and governed write capabilities in the commercial platform. Nautobot (Network to Code) offers an official MCP server with read-only queries and Jobs for workflow execution. IP Fabric's April 2026 MCP server deployment supports API-first integrations across ServiceNow, NetBox, Nautobot, Itential, Ansible, and Nornir. ContainerLab gained full MCP lifecycle support for lab provisioning. The report clarifies that source-of-truth platforms answer questions about records ("What devices are in site X?"), while orchestration tools (Itential) and labs (containerlab) enable agents to take action. For practitioners: if you're building agentic workflows, tool selection now hinges on whether it exposes an MCP server and how restrictively it gates writes.

Most enterprises use AI agents in operations without visibility

Dynatrace · Nov 10, 2026 · Primary source

Dynatrace research reveals 87% of enterprises use AI agents for observability and IT operations, while only 27% have visibility into how agents decide and act, exposing gaps in AI agent transparency, cost, and risk validation.

Why it matters NOC and SRE teams deploying agentic automation must establish observability-of-AI controls before delegating operational decisions to autonomous systems, shifting from detection to evidence-based governance.

The State of Observability 2026 report found that 87% of organisations use AI agents for observability and IT operations, while 44% target fully autonomous operations within five years, compared with 12% today. The research shows 43% consider visibility into agent decisions an important observability requirement, but only 27% currently address it. Observability budgets are expected to rise at 78% of organizations, with 96% citing AI adoption as at least a moderate driver; AI workloads increased computing and infrastructure spending for 81% of respondents, and only 27% address visibility into AI agents' decisions and actions, while humans verify an average of 66% of AI-powered decisions. Dynatrace distinguishes between observability of AI (establishing evidence about agent behaviour, output quality, security posture, cost, and business impact) and AI-powered observability (which applies causal analysis, automation, and agents to improve operations and advance autonomy). For practising network and SRE teams, this 16-percentage-point evidence gap—between what executives view as important (43%) and what's actually implemented (27%)—signals that autonomous agents remain operationally risky without proper audit trails.

Critical Windows LDAP remote code execution flaw patched

OPSWAT · Nov 12, 2026 · Industry news

CVE-2026-119958 is a Critical RCE vulnerability in Windows LDAP with CVSS 9.8, allowing unauthenticated attackers to execute arbitrary code via crafted LDAP calls. LDAP runs on every domain controller, making this a crown-jewels vulnerability requiring immediate patching across infrastructure.

Why it matters LDAP executes code in the domain controller itself; network teams must prioritize patching this and the four other critical infrastructure flaws (DNS, DHCP, Kerberos) across all Windows servers.

November 2026 Patch Tuesday includes five critical RCE flaws in core infrastructure services: LDAP (CVE-2026-119958, CVSS 9.8), DNS Server (CVE-2026-88218, CVSS 9.8), DHCP Server, and Kerberos. CVE-2026-119958 is an out-of-bounds write allowing unauthenticated network attackers to execute code in the LDAP service context on domain controllers with no sign-in needed—this is destructive on DCs and requires rapid testing and deployment. CVE-2026-88218 (Windows DNS RCE) is paired with three other DNS flaws that should be patched as a unit. Between DHCP Server (9 bugs, 4 RCE) and DNS (33 CVEs including 10 RCE), infrastructure services critical to most networks receive significant attention this month. These affect all versions from Windows Server 2016 through 2025 and Windows 10/11, making remediation scope enterprise-wide. Federal agencies have varying deadlines; test in isolated environments before production rollout.

Barracuda email gateway bypass chains to root in active attacks

Beazley Labs · Nov 10, 2026 · Industry news

CVE-2026-116606 is an authentication bypass in Barracuda Email Security Gateway allowing unauthenticated remote attackers to restore a crafted configuration backup. It chains with CVE-2026-111560 (command injection) to reach root access; active exploitation confirmed November 9.

Why it matters Barracuda confirmed active exploitation on November 9; CISA added both to KEV on November 10 with federal patch deadline November 13. Organizations with internet-exposed ESG admin interfaces face immediate compromise risk.

Barracuda published its advisory on November 2, 2026. CVE-2026-116606 is an authentication bypass in Email Security Gateway that lets a remote attacker restore a crafted configuration backup. On November 5 Barracuda updated the authentication field to 'No (Administrative UI Access Required).' If both flaws CVE-2026-116606 and CVE-2026-111560 are chained, an attacker can bypass authorization controls and gain root access to the appliance. CISA rated the bypass as automatable with total technical impact. For ESG appliances, upgrade to version 9.4.0.030 or greater to address both vulnerabilities. An ESG whose admin interface is reachable from the internet is the critical exposure—inventory these systems immediately and check for compromise indicators including unexpected configuration changes.

Attackers chain Check Point Gaia flaw to root on gateways

Rescana · Nov 13, 2026 · Industry news

CVE-2026-123039 is a CVSS 7.8 privilege escalation in Check Point Gaia OS DynamicCLI service. On November 12 Check Point confirmed attackers chained it with PHP2Shell vulnerabilities to gain root access on unpatched gateways; added to CISA KEV November 13.

Why it matters Check Point documented active exploitation in a three-CVE chain (PHP2Shell plus CVE-2026-123039) affecting dozens of systems October 30–November 4. Gateway teams must apply the November Jumbo Hotfix immediately to prevent documented active compromise.

The Gaia OS DynamicCLI daemon runs as root and listens on a world-writable local socket (/tmp/dynamic_socket) without authenticating connecting processes; an authenticated local user can send a command and execute it as root. Check Point gateways were targeted through a three-CVE attack chain: CVE-2026-109618 and CVE-2026-109619 (PHP2Shell) enabled initial access via Management API or Mobile Access portal, and CVE-2026-123039 was used for root privilege escalation and persistence. Check Point saw the chain used against a couple of dozen unpatched systems between October 30 and November 4, 2026, with a second wave on November 2 scanning organizations globally. Fix with November Jumbo Hotfix: R82.20 Take 14, R82.10 Take 52, R82 Take 132, or R81.20 Take 174 or later. Due date for federal agencies is November 16, 2026.

Anthropic lets customers self-host Claude managed agents

CASRAI · Nov 14, 2026 · Industry news

Anthropic launched self-hosted Claude Managed Agents on November 12, 2026, allowing customers to run the agent service, sandboxes and session storage in their own cloud or on-premises infrastructure. Agents, sessions and session history are stored on customer infrastructure, while model requests can go to a chosen inference provider.

Why it matters Self-hosted Claude Managed Agents extends customer control to the API, agent loop and session storage, enabling NetOps teams to run agentic infrastructure inside their security perimeter while controlling data residency and audit trails.

Previously, Claude Managed Agents ran only as a hosted service with Anthropic-operated infrastructure. Self-hosted sandboxes moved agent tool execution onto customer systems while Anthropic continued running the agent; tool inputs and outputs still flowed to Anthropic, which also stored skills and memory stores. The new option is fundamentally different: the self-hosted architecture centers on cma-server, which serves the Managed Agents API, runs the agent loop, stores agents, sessions and their histories, and calls the configured inference provider; separate workers execute shell and file tools inside customer sandboxes. A persistent deployment requires PostgreSQL 16 or later; without a database, the server retains data only in memory and a restart erases it. For infrastructure and SRE teams, this is a material shift: agents and their operational history stay inside your own cloud account or data center, model calls can route to Claude, Bedrock, Vertex, Foundry or a custom gateway, and every agent action is logged via OpenTelemetry. The private beta requires access request through Anthropic's account team.
