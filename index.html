Nautobot 3.2.8 patches dependency CVEs and adds HA guide

GitHub Releases · Oct 27, 2026 · Primary source

Nautobot v3.2.8 released October 27, 2026 addressing multiple security vulnerabilities including CVE-2026-114145 in GitPython, CVE-2026-114603 in OpenTelemetry SDK, and CVE-2026-115897. Added High Availability deployment guide and restricted queryset enhancements.

Why it matters Teams running Nautobot in production must update to patch CVE-2026-114145 (GitPython) and OpenTelemetry vulnerabilities; security-sensitive deployments using Nautobot for multi-tenant automation require queryset restriction updates.

Nautobot v3.2.8 (October 27, 2026) patches three upstream CVEs: GitPython CVE-2026-114145 (bumped to >=3.2.1,<3.3), OpenTelemetry SDK CVE-2026-114603 (1.45.1+), and npm serialize-javascript CVE-2026-115897. Core changes include restrict_queryset() added to nautobot.apps.models for multi-tenant environments—restricts querysets of users, groups, and other objects to only those a user has permission to act on. Added mock_wsgi_request() utility for constructing requests outside HTTP handlers (useful for testing automation jobs). Fixed metric registration during nautobot-server migrate (previously evaluated even when METRICS_ENABLED=False). Published High Availability deployment guide. For Nautobot practitioners integrating with Ansible or CI/CD, the queryset restriction is critical for safety in multi-tenant scenarios.

eMudhra issued certificates with keys crackable in seconds

Aviatrix Threat Research Center · Oct 23, 2026 · Analysis

Indian Certificate Authority eMudhra Limited issued eight TLS certificates with catastrophically weak private keys (3–8 bits of entropy instead of 384 bits for NIST P-384), enabling recovery of private keys and MITM attacks. Google removed emSign ECC Root CA-G3 from Chrome Root Store and blocked keys via CRLSet update on 27 October 2026.

Why it matters Well-resourced adversaries can trivially factor and recover private keys to mount MITM attacks against TLS sessions using eMudhra intermediates. Network teams must immediately audit certificate chains and implement pinning or revocation checking on all infrastructure relying on eMudhra-issued certificates.

The defect was a key-generation weakness so severe that eight intermediate CA private keys could be recovered directly from the public certificates. On 17 October, Mozilla received reports of the compromise; by October 20, Chrome, Firefox, Safari and Edge blocked the affected certificates. The keys were generated 30 April 2025 and went undetected for 18 months. Six intermediates handled TLS issuance, two handled code signing. Microsoft released out-of-band Windows updates KB5134133 and KB5134125 to distrust the compromised keys. Firefox, Chrome, Go, Python certifi and others issued emergency fixes within days; Node.js and Composer ca-bundle patches remained pending as of 28 October. This represents a systemic PKI failure requiring immediate verification of trust chains, CRL checking infrastructure, and certificate validation across all systems consuming eMudhra certificates. Organizations must audit their PKI pipelines to ensure automated validation of key entropy is performed before certificate issuance.

Node.js Brotli decoder flaw exploited for remote code execution

Help Net Security · Oct 27, 2026 · Industry news

Node.js released security updates on 21 October fixing CVE-2026-111497, an out-of-bounds write in the bundled Brotli decoder that allows remote code execution via malformed Brotli-compressed data. CISA added the flaw to Known Exploited Vulnerabilities catalog on 27 October with evidence of active exploitation in the wild.

Why it matters Applications decompressing untrusted Brotli data via fetch() API, Express 5 body-parser, or reverse proxies are at immediate risk. Infrastructure teams must upgrade Node.js to 22.23.4, 24.22.1, or 26.12.1 and audit ingress configurations for automatic Brotli decompression. End-of-life Node.js versions (20 and earlier) have no official fix.

CVE-2026-111497 scored CVSS 9.2 (critical) in CVSS v4.0. Brotli 1.0.10, 1.1.1 and 1.2.1 were released on 21 October with the fix. Threat intelligence firm ELLIO confirmed exploit traffic in the wild carrying a public proof-of-concept that achieves shell access on vulnerable builds. Microsoft released out-of-band .NET updates on 25 October for the same Brotli vulnerability in .NET's bundled copy, rated Critical for .NET and Visual Studio (CVSS 8.1 v3.1). The vulnerability affects applications accepting Brotli-compressed HTTP bodies, including those using automatic decompression in HttpClient, BrotliStream, or BrotliDecoder. Express 5 and body-parser 2.x transparently decode Content-Encoding: br request bodies, creating a default attack surface. Public exploits use crafted Brotli streams to drive the decoder's impossible distance-block switch into an invalid state, producing a controlled 16-byte out-of-bounds write that leads to heap corruption and code execution. Infrastructure teams should also patch .NET services, review Istio and service mesh Brotli handling, and monitor for suspicious Brotli-compressed requests.

Actively exploited PHP flaws hit all PAN-OS versions

Zetik · Oct 26, 2026 · Industry news

CISA added PHP2Shell flaws CVE-2026-109618 and CVE-2026-109619 to Known Exploited Vulnerabilities catalog on 26 October, confirming active exploitation. Both flaws allow unauthenticated remote code execution on PHP servers. Patches released 21 October; all versions of Palo Alto PAN-OS and Panorama affected with fixes rolling out through 30 October.

Why it matters PHP powers 73% of internet-facing web server workloads; Qualys found 156 million PHP installations with known versions on internet-facing assets and 110 million on end-of-life branches. Operations teams managing PAN-OS, Fortinet FortiMail, Cisco Secure Email, or any PHP-based management interfaces must patch immediately as this flaw directly compromises firewall, email security appliance, and web application firewall perimeters.

The PHP2Shell vulnerabilities are memory corruption flaws (memory corruption and stale internal request-state) enabling code execution without authentication under certain conditions. Exploitation occurred within days of public disclosure; Cloudflare, watchTowr and honeypot operators reported attack attempts or successful compromise shortly after. Qualys telemetry showed only 199,000 patches deployed in the first 12 hours across 156 million known PHP instances. Palo Alto Networks confirmed all PAN-OS and Panorama versions affected but saw only limited exploitation; fixed versions released October 27–30. Cisco Secure Email Gateway, Fortinet FortiMail (CVE-2026-104286, path traversal added to KEV 1 October), and other appliances with embedded PHP management interfaces also affected. The incident occurred during "Black October" when Microsoft reported a China-aligned group used AI tools to target hundreds of organizations, gaining privileged cloud access in under three hours on some victims. Teams must patch PHP-based management interfaces on all network appliances, isolate management interfaces from untrusted networks, review PHP error logs for anomalies, and monitor for credential compromise on affected devices.

OpenTelemetry eBPF instrumentation hits 1.0 with zero-code tracing

OpenTelemetry Blog · Oct 30, 2026 · Primary source

OpenTelemetry eBPF Instrumentation (OBI) v1.0.0 brings zero-code observability to running Linux applications using eBPF and runtime-specific instrumentation to capture metrics and traces across services, languages, and frameworks without code modification.

Why it matters Stable v1.0 foundation eliminates instrumentation friction in heterogeneous environments; SRE/AIOps teams can now deploy automatic telemetry capture across polyglot services without application changes or sidecars.

OBI v1.0.0 uses eBPF together with runtime-specific instrumentation to capture application metrics and traces across services, languages, and frameworks, starting with request rates, errors, latency, and service dependencies. Framework route discovery expanded to Django, FastAPI, Flask, Rails, .NET, and several PHP frameworks. The release fulfills the flagship goal set for 2026: establishing a stable foundation for OBI. It represents a year of expanding instrumentation coverage, improving correctness, strengthening release tooling, and building the compatibility and telemetry migration practices that users need to operate OBI over time. For users, the most important change is predictability: knowing what to expect from an upgrade and how to move forward when something changes. OBI can capture application-authored spans through supported OpenTelemetry Go Trace API and Auto SDK configurations, providing a path from automatic instrumentation to application-specific insight.
