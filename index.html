AutoCon 6 talk dissects automating from spreadsheet sources of truth

NIL (part of Conscia) · Oct 19, 2026 · Industry news

AutoCon 6 session abstract examining failure modes when automating network changes directly from manually-maintained spreadsheets. Covers data ownership, validation, governance, and scalability pitfalls with practical migration strategies to proper source-of-truth platforms like NetBox.

Why it matters Warns practitioners that source-of-truth data quality matters more than tooling—poor data governance embedded in automation exposes hidden process weaknesses and operational risks at scale.

Toni Sarađan's AutoCon 6 presentation (November 19, 2026) explores a scenario many network engineers recognize: Excel spreadsheets managing critical network information that become the foundation for automation projects. What appears initially successful quickly reveals broader challenges: data ownership gaps, lack of validation logic, governance failures, ad-hoc change control, and scaling brittleness. The session highlights practical lessons from automating against manually-maintained sources: when spreadsheets become the source of truth for network automation, operational risk increases dramatically because changes lack validation gates, audit trails are incomplete, and data consistency cannot be enforced. The presentation demonstrates real-world examples and live demonstrations of network changes automated directly from spreadsheet-based data sources, then contrasts this anti-pattern with proper migration strategies toward dedicated platforms. Key takeaway: the quality of source-of-truth data—validation logic, change control, and governance—matters far more than which tool you choose. Attendees gain practical insights into common failure modes and techniques for reducing risk through validation and governance, positioning NetBox (or Nautobot) adoption as a critical prerequisite for safe, scalable automation rather than a tool decision.

Ultra Ethernet aims to match InfiniBand as Broadcom silicon nears

Spheron · Oct 19, 2026 · Analysis

The Ultra Ethernet Consortium, formed in 2023 with AMD, Intel, HPE, Broadcom, Cisco, Meta, and Microsoft as founding members, aims for an open Ethernet RDMA fabric that matches InfiniBand latency without proprietary components. UEC 1.0 (published 2024) defines credit-based reliability in NIC firmware, eliminating head-of-line blocking. Broadcom's Tomahawk-UEC silicon is expected in 2026–2027.

Why it matters UEC 1.0 eliminates head-of-line blocking that makes RoCEv2 hard to operate at scale. This October 19 update provides operators a current decision framework: UEC hardware is still pre-production, making Spectrum-X the best production Ethernet option today if you need performance beyond vanilla RoCE.

The Ultra Ethernet Consortium, established in 2023 with AMD, Intel, HPE, Broadcom, Cisco, Meta, and Microsoft, targets an open Ethernet RDMA fabric for AI that matches InfiniBand latency without proprietary components. UEC 1.0 (published 2024) defines a transport protocol (Ultra Ethernet Transport) that avoids PFC entirely, using credit-based reliability implemented in NIC firmware rather than relying on switch-level pause frames, eliminating the head-of-line blocking problem that makes RoCEv2 difficult to operate at scale. UEC 1.0 also specifies hardware-offloaded collectives at the NIC level, not the switch level. Broadcom's Tomahawk-UEC silicon targeting UEC 1.0 is expected in 2026–2027. Until products ship, Spectrum-X is the best Ethernet option if you need better-than-vanilla-RoCE performance today. The article was updated October 19, 2026, providing a current practitioner snapshot of the InfiniBand-vs-Ethernet-vs-RoCE landscape as hardware transitions from Hopper (H100/H200) to Blackwell (B200) clusters.

RIPE NCC adds BGPsec router key certificates to RPKI API

RIPE NCC · Oct 23, 2026 · Primary source

RIPE NCC has introduced support for creating and managing BGPsec Router Key Certificates through the RPKI API, enabling AS holders to authorize router keys for signing BGP updates. This extends RPKI cryptographic protection beyond route origin validation to include path validation.

Why it matters Operators can now use the RPKI API to manage BGPsec keys programmatically, advancing cryptographic BGP security beyond ROA-based origin validation toward path-level authentication across the routing system.

The RIPE NCC Member Update for October 2026 announced a significant expansion of RPKI management capabilities: BGPsec Router Key Certificates are now supported through the RPKI API. This allows AS holders to create, manage, and revoke router keys used for signing BGP updates, adding a cryptographic layer of protection to BGP path validation. BGPsec Router Key Certificates complement existing Route Origin Authorization (ROA) capabilities by enabling end-to-end cryptographic verification of AS paths, not just route origins. This is a progression toward RFC 8205 BGPsec deployment, where routers can cryptographically sign updates and validate signatures from neighboring ASes. For operators managing large numbers of routers or multi-vendor environments, API-based management of BGPsec keys reduces manual provisioning overhead and improves auditability. However, adoption remains limited: BGPsec deployment is still not widespread on the global Internet, as it requires coordinated upgrades across ASes and carries operational complexity around key rotation and management.

Cloudflare Tunnel adds URL normalization for ingress rule matching

Cloudflare · Oct 22, 2026 · Primary source

Cloudflare Tunnel now supports URL normalization before matching ingress rules, starting with cloudflared 2026.10.0. The feature normalizes URLs for Access validation checks while keeping the path sent to origins unchanged; it will default to on from January 25, 2027.

Why it matters Network and security teams using Cloudflare Tunnel path-based routing must test their configurations before January 2027, as default URL normalization may change which ingress rule matches requests and affect traffic routing behavior.

Starting from cloudflared version 2026.10.0, Cloudflare Tunnel can normalize URLs before matching them against ingress rules. This feature improves security for tunnels with rules that require Cloudflare Access validation by standardizing URL format and reducing ambiguity in path-based rule matching. However, the URL path sent to the origin application remains unmodified, preserving backend application behavior. The feature is currently opt-in (off by default), but will become the default in new cloudflared releases starting January 25, 2027. This is a significant timeline for operators to test: any teams using path-based routing rules should validate their configurations before the default flip, as URL normalization can change which ingress rule matches a request—potentially redirecting traffic to different backends or requiring different Access policies. Configurations without rules requiring Access validation are unaffected. This change is part of Cloudflare's broader Tunnel hardening work and reflects a shift toward stricter URL parsing for security-sensitive routing decisions.

Eight eMudhra intermediate CA keys recovered from trivially weak entropy

The Hacker News · Oct 20, 2026 · Industry news

Eight eMudhra intermediate CA private keys were compromised with catastrophically weak entropy—3 to 8 bits instead of 384 bits required for NIST P-384. Chrome and Firefox blocked the eight certificates within hours of notification on October 17.

Why it matters Six keys could issue TLS certificates and two code-signing certificates; attackers could forge certificates for any website or service until revocation blocks distributed, enabling man-in-the-middle attacks on encrypted communications.

The Indian Certificate Authority eMudhra issued eight TLS certificates bearing catastrophically weak private keys, ranging from just 3 to 8 bits of entropy instead of the standard 384 bits required for NIST P-384 elliptic curve cryptography. On October 17, 2026, a security researcher reported that the private keys of eight intermediate CA certificates could be recovered due to insufficient randomness in key generation; within two hours, Google and Mozilla pushed blocks to Chrome and Firefox. The incident escalated from tactical intermediate blocks to global root cert distrust across Mozilla, the Google Chrome Root Store, Apple, and Microsoft. On October 22, 2026, eMudhra announced its decision to exit the global public SSL/TLS certificate business entirely. For network and infrastructure teams, this compromises the trust model for any TLS connection anchored to these certificates. Organizations should urgently audit certificate chains used for internal services, VPN termination, and API endpoints, verify whether any systems trust the affected eMudhra root or intermediates, and update OS trust stores and certificate bundles. Chrome is removing emSign ECC Root CA – G3 from its root store on October 27, 2026, which will break legitimate certificates chained to it.

HPE patches eight CVSS 10.0 flaws in Aruba wireless systems

BleepingComputer · Oct 23, 2026 · Industry news

HPE patched 72 vulnerabilities in Aruba AOS-8 and AOS-10 wireless operating systems on October 22, 2026, including eight maximum-severity authentication bypass and remote code execution flaws rated CVSS 10.0 exploitable without credentials through management interfaces and PAPI protocol.

Why it matters These flaws affect enterprise wireless infrastructure trusted by 90% of Fortune 500 companies; attackers can gain administrative control of mobility conductors, controllers, gateways, and access points without authentication through web management interfaces and PAPI.

HPE Networking patched 72 vulnerabilities in wireless operating systems AOS-8 and AOS-10 (ArubaOS) on October 22, 2026 via advisory HPESBNW05162. Eight flaws are rated CVSS 10.0: CVE-2026-79844 (AOS-10 authentication bypass leading to RCE), CVE-2026-79845 (AOS-10 authentication bypass in PAPI protocol), CVE-2026-79847 and CVE-2026-79851 (unauthenticated buffer overflows leading to RCE in AOS-10), CVE-2026-79846 (unauthenticated command injection in AOS-8), CVE-2026-79848 and CVE-2026-79849 (unauthenticated SQL injection allowing RCE in AOS-8), and CVE-2026-79850 (authentication bypass leading to RCE in AOS-8). HPE urges customers to patch quickly and restrict management interface access to dedicated network segments; no public exploit code or in-the-wild exploitation has been observed. This is a critical patch day for any organization running Aruba wireless controllers and access points. Prioritize patching mobility conductors, controllers, and gateways that expose management interfaces to the network, and restrict management traffic to dedicated administrative VLANs or IP ranges with firewall rules.
